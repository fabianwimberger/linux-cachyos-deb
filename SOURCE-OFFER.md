# Corresponding source

The kernel packages in each release are GPL-2.0 binaries, so GPL-2.0 §3 asks for the
complete corresponding source alongside them. That source is public and free to
download; this file says exactly which inputs a release was built from and how to
rebuild it.

## What a release is built from

Three things, all public:

| Input | Where | Pinned by |
| --- | --- | --- |
| CachyOS Linux 7.3.1 source tarball | https://github.com/CachyOS/linux/releases/download/cachyos-7.3.1-1/cachyos-7.3.1-1.tar.gz | `CACHY_SHA256` in `kernel.env` |
| Tarball signature | `cachyos-7.3.1-1.tar.gz.asc` next to it | `keys/cachyos-upstream.asc` |
| This repository at tag `v7.3.1` (commit `bd5f6b0`): `patches/`, `config/`, `docker/`, `scripts/`, `profiles/` | https://github.com/fabianwimberger/linux-cachyos-deb/tree/v7.3.1 | the tag |

The tarball plus this repository at that tag is the complete corresponding source for
`linux-image-7.3.1-cachyos-{x64v4,x64v3,znver4}` and their headers packages.

The tarball's SHA-256 is
`3dba29aa8e7dcda43aee6898e4c66dfbfd997eb5d902510b0faeacc696ddfb3f`.
`make fetch` downloads it, checks that hash and verifies the signature against the key
ring in `keys/` before anything is built, so a rebuild starts from the same bytes the
release did.

## Rebuild

On a machine with Docker:

```bash
git clone https://github.com/fabianwimberger/linux-cachyos-deb.git
cd linux-cachyos-deb
git checkout v7.3.1
make image        # build container with the pinned toolchain
make everything   # fetch, configure, build and package every flavour, then the apt index
```

`make everything` runs the same scripts the release did: `scripts/fetch.sh`,
`scripts/configure.sh` (Ubuntu 26.04 base config plus the fragments in
`config/fragments/`), `scripts/build.sh` (applies `patches/`, builds for the flavour in
`FLAVORS`), `scripts/package.sh`, `scripts/mkrepo.sh`. The debs land in `out/`, the apt
index in `repo/`.

## AutoFDO profile

Release builds are compiled with an AutoFDO profile, which is generated by running an
instrumented kernel and is not part of the source. It is an optimisation input only: a
rebuild without it — leave `AUTOFDO_PROFILE` unset — produces a working, functionally
identical kernel with a different code layout and somewhat lower performance.

The profile itself lives in a private repository (`AUTOFDO_PROFILES_REPO`), addressed by
the SHA-256 in `kernel.env`, so the same tag rebuilds with the same profile. It contains
no source code.
